You draw an aquarium creature, place it with the mouse in a real 3D underwater world – and it comes alive: it swims, wobbles, forms schools, gets hungry – and has to be fed.

04
Guiding principle
Two worlds: design time & runtime
03 · Principle
Design time
  • Drag components from the Tool Palette onto the form/viewport
  • Set properties in the Object Inspector (position, color, texture, passes)
  • Instant visual preview of the 3D scene inside the IDE
  • The result is stored in the .fmx file (form description)
  • Ideal for the static stage: walls, water, light, effects
Runtime / code
  • Everything dynamic & data-driven: building a mesh from a drawing
  • Creating, animating, removing objects at runtime
  • Behavior: swimming, schooling, feeding, persistence
  • Reacting to mouse & timer events
  • Lives in the .pas units
Rule of thumb: Whatever is fixed at design time gets clicked. Whatever only emerges through user input or per frame gets programmed.

Design time · Part 3  almost no code
Swappable backends
06 · Backends

Graphics, physics and audio are exchangeable layers underneath the same components – the scene itself stays unchanged.

🖥️OpenGL or Vulkan

Chosen once in the .dpr via Gorilla.Context.Backend, before Application.Initialize. SketchQuarium runs on both; on Win64 & Linux64 it uses Vulkan (needs shaderc_shared.dll).

🧲Jolt or Q3 physics

PhysicsSystem.Driver = JOLTPhysics (native Jolt, Jolt64.dll) or Q3Physics (the embedded engine, no extra DLL). The colliders stay the same – it is one property in the Object Inspector.

🔊FMOD or OpenAL audio

TGorillaFMODAudioManager (fmodL64.dll) or TGorillaOpenALManager – both descend from TGorillaAudioManager. SketchQuarium uses FMOD with an Effects channel group.

// SketchQuarium.dpr — before Application.Initialize
TGorillaSystem.ForceToUseNVIDIAorAMDGPU();  // dedicated GPU
{$IF Defined(MSWINDOWS) AND Defined(CPUX64)}
GorillaGraphicsBackend := TGorillaGraphicsBackend.gbVulkan;
{$ENDIF}
// gbDefault / gbOpenGL = OpenGL (platform default)
macOS ARM & Metal: Gorilla3D supports Metal in principle. SketchQuarium itself has not been tested on macOS ARM yet – so no promise from my side, but nothing in the app is Windows-specific by design.

Everything so far was static. The real appeal of SketchQuarium is user-generated – and no designer can anticipate that.

🎨→🧊Drawing → 3D object

Painting inside the shape
10 · Editor

“How do I colour inside the fish?” Pick a shape, paint freely – the stencil keeps every stroke inside.

SVG
SVG stencil
assets/shapes/<kind>/*.svg – loaded at start, filtered by kind
→
SKIA
Mask
rendered white at 600×600 px; alpha → coverage 0..1 per pixel
→
GUIDE
Contour
edge pixels of the mask, a TImage on top – never saved
→
STROKE
Brush + clip
paint into the bitmap, then cap alpha to the mask
Four brushes, one bitmap
  • Round – Canvas.DrawLine with round caps and joins
  • Soft / extra soft – smoothstep edge per pixel; a snapshot of the stroke start + a max-coverage buffer → no colour build-up where a stroke crosses itself
  • Elongated – rotated ellipse stamps (45° nib) → calligraphic strokes
  • Eraser – pixels back to transparent · Freehand = no stencil at all
// ApplyStencilClip — per pixel in the stroke's box
m  := FStencilMask[yy * W + xx];      // 0 outside .. 1 inside
if m >= 0.999 then Continue;          // fully inside: untouched
px := TAlphaColorRec(LData.GetPixel(xx, yy));
ma := Round(m * 255);
if px.A > ma then                    // cap, never add → min()
begin
  px.A := ma;
  LData.SetPixel(xx, yy, px.Color);
end;

→ The finished 600×600 bitmap keeps its alpha channel: that transparency becomes the creature's silhouette in 3D (alpha cutout, Detail 3).

Gorilla3D's CustomMesh approach: geometry, material and animation are described as a definition (TModelDef), and an instance is created from it.

// Aquarium.Elements — BuildModelDef: a subdivided quad as geometry
LData := TMeshData.Create();
LData.VertexBuffer.Length := (N+1)*(N+1);           // N = 24 subdivisions
for Y := 0 to N do for X := 0 to N do
begin
  LData.VertexBuffer.Vertices[idx]  := Point3D(-0.5+X/N, -0.5+Y/N, 0);  // flat grid
  LData.VertexBuffer.TexCoord0[idx] := PointF(X/N, Y/N);          // UVs for the texture
end;
LMesh.ApplyFromMeshData(LData);

Detail 3  programmed
The sprite material
12 · Material
Goal: the drawing as a “sticker”
  • Unlit – the painted colors stay original
  • Visible from both sides (the fish turns around)
  • Alpha cutout: transparent painted areas stay see-through
  • The texture comes from the drawn bitmap at runtime
Pitfall “black fish”: Gorilla forces lighting internally – when turning around, the fish went black. Solution: after materializing, disable lighting recursively on the material (DisableLighting). 
// configure the material like a sprite
LMat := TMaterialDef.Create(Result, 'mat');
LMat.Kind          := mkBlinnPhong;
LMat.UseTexturing  := True;
LMat.UseLighting   := False;   // true colors
LMat.UseSpecular   := False;
LMat.DoubleSided   := True;    // both sides
LMat.UseAlphaCutoff := True;
LMat.AlphaCutoff    := 0.1;     // crisp silhouette

// drawn bitmap as texture (gets cloned)
LAsset := TGorillaTextureAsset.Create(nil);
LAsset.ImportFromCachedBitmap('drawing.png', ABitmap);
LMat.AddTexture(TColorChannelDef.Diffuse, LAsset, True);
LMesh.SetMaterialReference(LMat);

Detail 4  programmed
Animation on two levels
13 · Animation
① Own animation (wobbling)
  • Baked vertex animation in the ModelDef
  • Keyframes are precomputed over one loop period (DeformedVertex)
  • Fish: traveling wave with an emphasized tail fin
  • Two loops: self (calm) & fast (hunting)
  • The framework plays them back – close to the GPU
② Spatial movement (swimming)
  • Integrated in code per frame (velocity)
  • Decoupled from wobbling → precisely controllable
  • Aligns the heading with the movement
  • Foundation for schooling & food hunting
Lesson: The loop is part of the definition (LInter.Loop := True); switching loops at runtime is one call: PlayAnimation('fast').

→ Separating shape deformation from locomotion keeps the logic clean and flexible.

Detail 5  programmed
The fish wobble, computed
14 · Wobble
DeformedVertex(u, v, θ)
  • Input: a grid point (u, v) in −0.5..0.5 and the loop angle θ in 0..2π
  • Tail weight w = 0.5 − u → 1 at the tail fin, 0 at the head
  • Travelling wave sin(6u − speed·θ), amplitude × wtailPow
  • Displacement: Z = 0.5·wave (fin beat) + Y = 0.05·wave (visible from the front)
  • speed is an integer → the wave at θ = 2π equals θ = 0: a seamless loop
  • Jellyfish: pulsing bell + trailing hem · plants & corals: sway with a fixed root (w², w³)
// Aquarium.Elements — AddWobble bakes 25 keyframes
for k := 0 to ANIM_KEYS do                  // ANIM_KEYS = 24
begin
  theta := 2 * PI * (k / ANIM_KEYS);
  // … for all 25 × 25 grid points:
  verts[i] := DeformedVertex(AKind, u, v, theta,
                AAmp, ASpeed, ATailPow, ARamp);
  LInter.AddKey(k / ANIM_KEYS, verts, Linear); // TMeshInterpolatorDef
end;

fast0.85 s1.422.50.6

→ FastSwim := True calls AnimationManager.PlayAnimation('fast') – a hunting fish beats its tail faster. Ramp lets the beat build up within the loop and fall back to 1 at the loop point. Baked once per template, shared by every instance.

Detail 6  programmed
Life in the scene: schools & food
15 · Behavior

TAquariumScene.SteerFish contains a classic boids model – three simple rules produce believable schooling behavior.

↔️Separation

Keep your distance – force ∝ 1/d² to all fish.

🧭Alignment

Match the heading – only with the same species (species ID).

🎯Cohesion

Steer toward the school's center – also same species only.

🍤Food hunting

DropFood drops a sinking pellet; only hungry fish get a pellet assigned (AssignFood), switch to fast and eat it.

🪼Jellyfish & boundaries

SteerJelly: gentle 3D wandering + vertical bobbing. Everyone stays within the tank boundaries (bounce).

  • Health drops by 0.5 HP/s – about 3:20 min from full to dead
  • Each pellet gives +30 HP; at 100 HP the fish is sated again
  • AssignFood: one pellet per fish, one fish per pellet – the hungriest wins (distance − 0.06 × missing HP)
  • Health is saved with each fish (collectable parameter)
The fish is the health bar: no extra UI – the material of each instance is tinted. Pitfall: unlit color = texture × (ambient + diffuse + specular), so the whole sum is moved into diffuse before blending.
// Aquarium.Elements — UpdateHealth (per fish, every frame)
if AFish.FSatedTime > 0 then
  AFish.FSatedTime := AFish.FSatedTime - ADt        // still full
else
  AFish.FHealth := AFish.FHealth - FISH_HUNGER_RATE * ADt;

if AFish.FHealth <= 0 then
begin                                    // starved
  AFish.FDead := True;
  SetTint(AFish, TINT_DEAD, 1);                  // grey
  AFish.FModel.AnimationManager.Current.StopAtCurrent();
  AFish.FModel.RotationAngle.X := 180;           // belly-up
end;

From practice
Lessons & best practices
19 · Lessons

🧩Design time first

Compose as much as possible from components. Write code only for the dynamic parts – that saves an enormous amount of effort.

🔑Understand def ownership

By default a model owns its TModelDef and frees it. SketchQuarium shares one cached def per template → IsDefOwner := False, and the scene frees the defs – once no fish uses them any more.

💡UseLighting trap

Gorilla forces lighting internally – for the sprite look, disable lighting after materializing.

🔁Seamless loops

Every time term must be a whole multiple of θ – then the last baked keyframe equals the first and the loop never jumps.

🧭Separate responsibilities

Drawing, placement, scene and catalog each in their own units – Unit1 stays lean “glue”.

🧵One timer, one dt

Integrate based on time instead of per frame – same behavior at any frame rate.

Summary
Key takeaways
20 · Conclusion
  • Delphi + Gorilla3D combines visual composition with full code control – ideal for ambitious 3D apps.
  • The static stage (water, caustics, physics, bubbles, sound) is created almost entirely at design time without code.
  • The creative, dynamic core – drawing → mesh → animation → schooling → persistence – is cleanly encapsulated code.
  • The CustomMesh/ModelDef approach is the key to turning user content into real 3D objects at runtime.
  • Two separate animation levels + a time-based loop make the world alive and controllable.
  • Swappable backends: OpenGL or Vulkan, Jolt or Q3, FMOD or OpenAL – one line in the .dpr or one property.
