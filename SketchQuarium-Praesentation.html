Die Idee
Was ist SketchQuarium?
01 · Überblick

Man zeichnet ein Aquariumstier, platziert es per Maus in einer echten 3D-Unterwasserwelt – und es lebt: schwimmt, wabbelt, bildet Schwärme, bekommt Hunger – und will gefüttert werden.

SCHRITT 1
🎨 Zeichnen
Fisch, Qualle, Pflanze oder Koralle im 2D-Editor malen
→
SCHRITT 2
🧊 Materialisieren
Zeichnung wird zu einem texturierten 3D-Mesh
→
SCHRITT 3
🖱️ Platzieren
Vorschau folgt der Maus, Klick setzt die Instanz
→
SCHRITT 4
🌊 Leben
Eigen­animation, Schwarm, Fütterung & Lebens­punkte

🧩Fertige Bausteine

Wasser, Kaustik, Physik, Blasen, Sound – vieles kommt aus Gorilla3D-Komponenten, ganz ohne Code.

✍️Eigener Inhalt

Der kreative Kern – Zeichnung → Mesh → Animation → Verhalten – ist programmiert.

💾Persistenz

Vorlagen & ganze Aquarien werden als XML + PNG gespeichert und wieder geladen.

Leitprinzip
Zwei Welten: Entwurfszeit & Laufzeit
03 · Prinzip
Entwurfszeit
  • Komponenten aus der Tool-Palette auf Formular/Viewport ziehen
  • Eigenschaften im Objektinspektor setzen (Position, Farbe, Textur, Pässe)
  • Sofortige visuelle Vorschau der 3D-Szene in der IDE
  • Ergebnis liegt in der .fmx-Datei (Formularbeschreibung)
  • Ideal für die statische Bühne: Wände, Wasser, Licht, Effekte
Laufzeit / Code
  • Alles Dynamische & Datenabhängige: aus einer Zeichnung ein Mesh bauen
  • Objekte zur Laufzeit erzeugen, animieren, entfernen
  • Verhalten: Schwimmen, Schwarm, Fütterung, Persistenz
  • Reaktion auf Maus- & Timer-Ereignisse
  • Liegt in den .pas-Units
Faustregel: Was zur Entwurfszeit feststeht, wird geklickt. Was erst durch Benutzer­eingabe oder pro Frame entsteht, wird programmiert.

Entwurfszeit · Teil 3  fast ohne Code
Austauschbare Backends
06 · Backends

Grafik, Physik und Audio sind austauschbare Schichten unter denselben Komponenten – die Szene selbst bleibt unverändert.

🖥️OpenGL oder Vulkan

Einmal in der .dpr über Gorilla.Context.Backend gewählt, vor Application.Initialize. SketchQuarium läuft unter beiden; unter Win64 & Linux64 nutzt es Vulkan (braucht shaderc_shared.dll).

🧲Physik: Jolt oder Q3

PhysicsSystem.Driver = JOLTPhysics (natives Jolt, Jolt64.dll) oder Q3Physics (die eingebettete Engine, ohne DLL). Die Collider bleiben gleich – es ist eine Eigenschaft im Objektinspektor.

🔊Audio: FMOD oder OpenAL

TGorillaFMODAudioManager (fmodL64.dll) oder TGorillaOpenALManager – beide erben von TGorillaAudioManager. SketchQuarium nutzt FMOD mit einer Effects-Kanalgruppe.

// SketchQuarium.dpr — vor Application.Initialize
TGorillaSystem.ForceToUseNVIDIAorAMDGPU();  // dedizierte GPU
{$IF Defined(MSWINDOWS) AND Defined(CPUX64)}
GorillaGraphicsBackend := TGorillaGraphicsBackend.gbVulkan;
{$ENDIF}
// gbDefault / gbOpenGL = OpenGL (Plattform-Standard)
macOS ARM & Metal: Gorilla3D kann Metal grundsätzlich. SketchQuarium selbst ist unter macOS ARM noch nicht getestet – daher kein Versprechen von mir, aber die Anwendung ist nicht bewusst Windows-spezifisch gebaut.

Der CustomMesh-Ansatz von Gorilla3D: Geometrie, Material und Animation werden als Definition (TModelDef) beschrieben und daraus eine Instanz erzeugt.

// Aquarium.Elements — BuildModelDef: ein unterteiltes Quad als Geometrie
LData := TMeshData.Create();
LData.VertexBuffer.Length := (N+1)*(N+1);           // N = 24 Unterteilungen
for Y := 0 to N do for X := 0 to N do
begin
  LData.VertexBuffer.Vertices[idx]  := Point3D(-0.5+X/N, -0.5+Y/N, 0);  // flaches Gitter
  LData.VertexBuffer.TexCoord0[idx] := PointF(X/N, Y/N);          // UVs für die Textur
end;
LMesh.ApplyFromMeshData(LData);

Das Sprite-Material
12 · Material
Ziel: Zeichnung als „Sticker“
  • Unbeleuchtet – die gemalten Farben bleiben original
  • Beidseitig sichtbar (Fisch dreht um)
  • Alpha-Cutout: transparente Malbereiche bleiben durchsichtig
  • Textur kommt aus dem gezeichneten Bitmap zur Laufzeit
Stolperfalle „schwarzer Fisch“: Gorilla erzwingt intern Beleuchtung – beim Umdrehen wurde der Fisch schwarz. Lösung: nach dem Materialisieren das Licht am Material rekursiv abschalten (DisableLighting). 
// Material wie ein Sprite konfigurieren
LMat := TMaterialDef.Create(Result, 'mat');
LMat.Kind          := mkBlinnPhong;
LMat.UseTexturing  := True;
LMat.UseLighting   := False;   // echte Farben
LMat.UseSpecular   := False;
LMat.DoubleSided   := True;    // beidseitig
LMat.UseAlphaCutoff := True;
LMat.AlphaCutoff    := 0.1;     // harte Silhouette

// gezeichnetes Bitmap als Textur (wird geklont)
LAsset := TGorillaTextureAsset.Create(nil);
LAsset.ImportFromCachedBitmap('drawing.png', ABitmap);
LMat.AddTexture(TColorChannelDef.Diffuse, LAsset, True);
LMesh.SetMaterialReference(LMat);

Detail 4  programmiert
Animation auf zwei Ebenen
13 · Animation
① Eigen-Animation (Wabbeln)
  • Gebackene Vertex-Animation im ModelDef
  • Über eine Loop-Periode werden Keyframes vorberechnet (DeformedVertex)
  • Fisch: Wanderwelle mit betonter Schwanzflosse
  • Zwei Loops: self (ruhig) & fast (Jagd)
  • Die Engine spielt sie ab – GPU-nah
② Raum-Bewegung (Schwimmen)
  • Im Code pro Frame integriert (Geschwindigkeit)
  • Entkoppelt vom Wabbeln → gezielt steuerbar
  • Richtet die Blickrichtung nach der Bewegung aus
  • Grundlage für Schwarm & Futter-Jagd
Lektion: Der Loop steckt in der Definition (LInter.Loop := True); umgeschaltet wird zur Laufzeit mit einem Aufruf: PlayAnimation('fast').

→ Trennung von Form-Deformation und Ortsbewegung hält die Logik sauber und flexibel.

Detail 5  programmiert
Das Fisch-Wabbeln, berechnet
14 · Wabbeln
DeformedVertex(u, v, θ)
  • Eingabe: ein Gitterpunkt (u, v) in −0.5..0.5 und der Loop-Winkel θ in 0..2π
  • Schwanzgewicht w = 0.5 − u → 1 an der Schwanzflosse, 0 am Kopf
  • Wanderwelle sin(6u − speed·θ), Amplitude × wtailPow
  • Auslenkung: Z = 0.5·wave (Flossenschlag) + Y = 0.05·wave (auch frontal sichtbar)
  • speed ist ganzzahlig → die Welle bei θ = 2π gleicht θ = 0: nahtloser Loop
  • Qualle: pulsierende Glocke + nachziehender Saum · Pflanze & Koralle: Wiegen mit fester Wurzel (w², w³)
// Aquarium.Elements — AddWobble backt 25 Keyframes
for k := 0 to ANIM_KEYS do                  // ANIM_KEYS = 24
begin
  theta := 2 * PI * (k / ANIM_KEYS);
  // … für alle 25 × 25 Gitterpunkte:
  verts[i] := DeformedVertex(AKind, u, v, theta,
                AAmp, ASpeed, ATailPow, ARamp);
  LInter.AddKey(k / ANIM_KEYS, verts, Linear); // TMeshInterpolatorDef
end;

→ FastSwim := True ruft AnimationManager.PlayAnimation('fast') – ein jagender Fisch schlägt schneller. Ramp lässt den Schlag innerhalb des Loops anschwellen und am Loop-Punkt auf 1 zurückkehren. Gebacken einmal je Vorlage, geteilt von allen Instanzen.

Aus der Praxis
Lektionen & Best Practices
19 · Lessons

🧩Entwurfszeit zuerst

So viel wie möglich als Komponente komponieren. Code nur für das Dynamische – das spart enorm viel Aufwand.

🔑Def-Eigentum verstehen

Standardmäßig besitzt ein Modell sein TModelDef und gibt es frei. SketchQuarium teilt eine gecachte Def je Vorlage → IsDefOwner := False, und die Szene gibt die Defs frei – sobald kein Fisch sie mehr nutzt.

💡UseLighting-Falle

Gorilla erzwingt Beleuchtung intern – für den Sprite-Look das Licht nach dem Materialisieren abschalten.

🔁Nahtlose Loops

Jeder Zeitterm muss ein ganzzahliges Vielfaches von θ sein – dann gleicht der letzte gebackene Keyframe dem ersten und der Loop springt nie.

🧭Verantwortungen trennen

Zeichnen, Platzieren, Szene, Katalog jeweils in eigene Units – Unit1 bleibt schlanker „Klebstoff“.

🧵Ein Timer, ein dt

Zeit­basiert integrieren statt pro Frame – gleiches Verhalten bei jeder Framerate.

Zusammenfassung
Was mitzunehmen ist
20 · Fazit
  • Delphi + Gorilla3D verbindet visuelles Komponieren mit voller Code-Kontrolle – ideal für 3D-Apps mit Anspruch.
  • Die statische Bühne (Wasser, Kaustik, Physik, Blasen, Sound) entsteht fast vollständig zur Entwurfszeit ohne Code.
  • Der kreative, dynamische Kern – Zeichnung → Mesh → Animation → Schwarm → Persistenz – ist sauber gekapselter Code.
  • Der CustomMesh/ModelDef-Ansatz ist der Schlüssel, um Nutzerinhalte zur Laufzeit in echte 3D-Objekte zu verwandeln.
  • Zwei getrennte Animationsebenen + ein zeitbasierter Loop machen die Welt lebendig und steuerbar.
  • Austauschbare Backends: OpenGL oder Vulkan, Jolt oder Q3, FMOD oder OpenAL – eine Zeile in der .dpr oder eine Eigenschaft.
